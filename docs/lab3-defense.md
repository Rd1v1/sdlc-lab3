# LAB 3 — шпаргалка защиты

Хэш — результат одностороннего преобразования. Перебор не декодирует хэш, а генерирует гипотезы и проверяет каждую.

`lab3/src/bruteforce.py`: `CrackConfig.validate` ограничивает длину/алфавит/число кандидатов. `candidate_at` представляет индекс в системе счисления с основанием длины алфавита; `iter_candidates` проходит все индексы каждой длины. `HashTarget.parse` определяет формат и ограничивает параметры KDF; `matches` выполняет hashlib или проверку bcrypt/Argon2id.

`crack`: последовательный цикл либо ThreadPoolExecutor. Пространство каждой длины делится на непересекающиеся интервалы `[start,end)`, каждый submit получает свой интервал. Event останавливает новые проверки после успеха; уже начатые проверки учитываются. Future возвращает найденный пароль и фактический счётчик; счётчики суммируются. finally останавливает работу и при прерывании/ошибке.

GIL и накладные расходы мешают масштабировать короткие Python/MD5/SHA1 задачи; дорогие нативные KDF могут освобождать GIL. У Argon2 есть собственный parallelism, поэтому внешние workers не равны числу реально загруженных ядер. Сравнение делается по измерениям, не по обещанию «два потока быстрее».

`benchmark.py`: фиксированные соли только для учебной воспроизводимости; реальные perf_counter timings; повторные прогоны, CSV/JSON и медианы. Контроль: одинаковые типы хэша, длина, алфавит и позиция. A**L — размер пространства; увеличение позиции меняет число попыток без изменения стойкости алгоритма.

Demo: `./scripts/run_lab3.ps1 4a8a08f09d37b73795649038408b5f33 --alphabet abc --min-length 1 --max-length 1` → c, 3 попытки. Заменить alphabet на ab → not found, код 1. `invalid` → код 2. Открыть `docs/lab3-analysis.md` и `benchmarks/results.csv`.

Hashcat получает тот же wordlist, cache/potfile результатов отключён. Его process wall time включает инициализацию GPU; он не сравним с чистой скоростью kernel. Неизвестные сложные исходные хэши не названы найденными.
