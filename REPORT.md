## Сравнение времени поиска пароля

Одинаковое задание: проверить варианты a, b, c и найти пароль c. В таблице медианное время успешных запусков. Меньше время — быстрее выполнено это задание. У приложения учтены создание воркеров и поиск; у hashcat — запуск, подготовка GPU и поиск.

| Алгоритм | Вариантов пароля в наборе | Моё приложение: время, с | Hashcat: время, с |
| --- | ---: | ---: | ---: |
| MD5 | 3 | 0.000302 | 2.483962 |
| SHA-1 | 3 | 0.000492 | 2.394979 |
| bcrypt | 3 | 0.166996 | 10.425126 |
| Argon2id | 3 | 0.275684 | 3.374385 |

Режим приложения: потоки; воркеров: 1. Для каждого алгоритма запусков приложения: 3; запусков hashcat: 3.

## Скорость выполнения задания с учётом запуска

Здесь скорость = число вариантов пароля в наборе ÷ полное время выполнения. Для обоих инструментов используется одна формула. Это показывает, сколько кандидатов приходится на секунду общего времени, включая подготовку инструмента.

| Алгоритм | Моё приложение: кандидатов/с | Hashcat: кандидатов/с |
| --- | ---: | ---: |
| MD5 | 9923.92 | 1.208 |
| SHA-1 | 6102.52 | 1.253 |
| bcrypt | 17.96 | 0.288 |
| Argon2id | 10.88 | 0.889 |

Это эффективная скорость короткого задания, а не скорость GPU во время самого перебора. На трёх кандидатах большую часть времени hashcat занимает подготовка. Например, для MD5: 3 варианта ÷ полное время hashcat. Из этой таблицы нельзя сделать вывод, что приложение быстрее GPU на большом наборе.

bcrypt: cost=10. Argon2id: m=65536 KiB, t=3, p=2. «Нет замера» означает отсутствие успешного сопоставимого запуска.
