# Практика 3. Перебор паролей и анализ скорости

## Цель

Реализовать офлайн-поиск пароля по хэшу, проверить корректность четырёх алгоритмов и исследовать влияние длины, алфавита и параллельного выполнения.

## Устройство приложения

Генерация кандидатов отделена от проверки хэшей, CPU/GPU-поиска и CLI. CPU-режим делит индексируемый диапазон между потоками или процессами. GPU-режим передаёт пакеты кандидатов OpenCL-ядрам через PyOpenCL. Работа с удалёнными учётными записями отсутствует. Hashcat запускается отдельно.

## Проверка требований

| Требование | Выполненная проверка |
| --- | --- |
| MD5, SHA-1, bcrypt, Argon2id | Тестовые векторы CPU и сравнение полных GPU-дайджестов |
| Данные задания | Все 16 хэшей проверены GPU-поиском по кандидатам `123456` и `apple`: восемь easy/medium найдены; восемь hard/very_hard отсутствуют в этом диапазоне |
| Перебор диапазона | Найденный пароль, исчерпание, границы, число проверок |
| Потоки и процессы | Разбиение без пропусков/повторов, остановка и освобождение воркеров |
| Выбор воркеров и визуализация | Несколько потоков/процессов или GPU-слотов; кандидаты, счётчики и подтверждённый пароль каждого воркера |
| GPU и словарь | Четыре алгоритма, бинарные строки, длины, память, недоступное устройство |
| Скорость и сложность | 288 CPU-замеров: длина, алфавит, позиция и число воркеров |
| Сравнение с hashcat | 24 запуска приложения и 24 отдельных запуска hashcat на GPU |

Все 46 выполняемых тестов прошли. Один тест группового POSIX-сигнала пропущен на Windows. В том числе выполнены 11 реальных GPU-тестов. Ошибки ввода, отмена через обработчик, очистка потоков и процессов проверены отдельными тестами. Зависимости `.venv` согласованы. Дополнительный статический анализ Bandit не выявил находок HIGH.

Параметр `--workers` задаёт число CPU-потоков/процессов или параллельных кандидатов в GPU-пакете. GPU-воркер — повторно используемый слот пакета. Таблица CLI отдельно показывает текущий кандидат и подтверждённый пароль; у воркеров без совпадения в результате стоит `-`. Счётчики GPU-слотов накапливаются между пакетами, а при коротком последнем пакете сохраняется последняя проверка неактивных слотов. Проверены также несколько совпадений при повторяющихся строках словаря.

Команды из README выполнены для GPU с четырьмя воркерами, двух CPU-потоков, двух процессов, полного RockYou и исчерпанного диапазона. Получены ожидаемые пароли, коды завершения и результаты в таблице. Сравнительные замеры ниже сохранены из предыдущей серии; повторная функциональная проверка не выдаётся за новые измерения производительности.

## Сравнение с hashcat

Оба приложения используют GPU. В таблице — медиана трёх запусков, время в секундах.

| Алгоритм | Режим | Моё приложение, с | hashcat, с |
| --- | --- | ---: | ---: |
| MD5 | Без словаря | 0.764 | 2.404 |
| MD5 | RockYou | 1.039 | 2.725 |
| SHA-1 | Без словаря | 0.738 | 2.513 |
| SHA-1 | RockYou | 1.046 | 2.953 |
| bcrypt | Без словаря | 1.286 | 8.762 |
| bcrypt | RockYou | 1.655 | 11.357 |
| Argon2id | Без словаря | 0.911 | 5.912 |
| Argon2id | RockYou | 1.237 | 2.866 |

Без словаря: маска `12345?d`, 10 вариантов. RockYou: полный словарь из 14 344 391 строк, пароль `123456` находится в первой строке. Поиск прекращается после находки; время не означает проверку всего словаря.

Измеряется полное время отдельного процесса, включая подготовку GPU. В моём приложении при работе со словарём также учитывается проверка файла. Это время выполнения указанного задания, а не пиковая скорость хэширования.

bcrypt: cost=10. Argon2id: m=65536 КиБ, t=3, p=2. Для обоих инструментов использованы одинаковые хэши и наборы кандидатов, GPU-запуски выполнялись последовательно.

## Влияние длины и алфавита

Ниже CPU-режим с одним потоком. Последний кандидат является паролем; медианы трёх запусков. Для длины L и алфавита A пространство равно A^L.

| Алфавит | Длина | Вариантов | MD5, с | Argon2id, с |
| --- | ---: | ---: | ---: | ---: |
| abc | 1 | 3 | 0.000470 | 0.260354 |
| abc | 2 | 9 | 0.000437 | 0.813785 |
| abc | 3 | 27 | 0.000532 | 2.668629 |
| abcd | 2 | 16 | 0.000438 | 1.621355 |

При увеличении длины от 1 до 3 алфавит abc даёт 3 → 9 → 27 вариантов. При длине 2 переход от abc к abcd даёт 9 → 16. Для быстрых хэшей на малых наборах заметен шум запуска; bcrypt и Argon2id показывают стоимость самой проверки.

## Влияние числа воркеров

Перебираются 27 вариантов длины 3 из abc. Во всех строках используется CPU. GPU-сравнение приведено отдельно выше.

| Алгоритм | 1 поток, с | 2 потока, с | 1 процесс, с | 2 процесса, с |
| --- | ---: | ---: | ---: | ---: |
| MD5 | 0.000532 | 0.000479 | 0.209272 | 0.207214 |
| SHA-1 | 0.000409 | 0.000418 | 0.186288 | 0.241641 |
| bcrypt | 1.488606 | 0.816694 | 1.689332 | 1.014805 |
| Argon2id | 2.668629 | 1.618700 | 2.603906 | 1.620028 |

Для MD5/SHA-1 на коротком поиске создание процессов дороже вычислений. В измеренных случаях bcrypt и Argon2id ускоряются при двух воркерах; эффект зависит от стоимости проверки, памяти и внутренних потоков KDF.

## Ограничения и вывод

Повышение длины и размера алфавита увеличивает пространство перебора, а bcrypt/Argon2id повышают цену одной проверки. Время до находки зависит от позиции пароля. Короткий поиск с подготовкой устройства не позволяет оценить пиковую производительность инструментов.

Неизвестные пароли hard/very_hard не объявляются найденными. Поддерживается ограниченный диапазон, выбранный пользователем. GPU-кандидаты ограничены 256 байтами, bcrypt — 72; GPU Argon2id использует 32-байтовый digest. CPU не подставляется вместо недоступной GPU.

OpenCL-примитивы используются как библиотека с сохранённой MIT-лицензией. Приложение реализует генерацию кандидатов, управление вычислениями и поиск; исполняемый файл hashcat для этого не вызывается.

## Команды отдельного сравнения

Hashcat запускается отдельно. Скачайте архив с [официального сайта](https://hashcat.net/hashcat/) и распакуйте его так, чтобы файл находился в `.tools/hashcat/hashcat-7.1.2/hashcat.exe`. Установка hashcat не нужна для работы моего приложения.

Пример отдельного GPU-поиска MD5 пароля `123456`, без словаря и с тем же RockYou:

```powershell
$wordlist = (Resolve-Path .tools/wordlists/rockyou.txt).Path
Push-Location .tools/hashcat/hashcat-7.1.2
./hashcat.exe --backend-ignore-cuda --backend-ignore-hip -D 2 -d 1 --potfile-disable --restore-disable --logfile-disable -m 0 -a 3 --markov-disable e10adc3949ba59abbe56e057f20f883e '12345?d'
./hashcat.exe --backend-ignore-cuda --backend-ignore-hip -D 2 -d 1 --potfile-disable --restore-disable --logfile-disable --wordlist-autohex-disable -m 0 -a 0 e10adc3949ba59abbe56e057f20f883e $wordlist
Pop-Location
```

Для других хэшей замените значение хэша и `-m`: MD5 — `0`, SHA-1 — `100`, bcrypt — `3200`, Argon2id — `34000`. Учебные хэши находятся в [assignment-hashes.json](lab3/examples/assignment-hashes.json). Для сравнения запустите моё приложение с `--backend gpu --no-progress` на том же хэше и наборе кандидатов. Для полного времени запуска используйте `Measure-Command`, направив вывод команды в `Out-Host`; выполните три последовательных запуска и возьмите медиану.
