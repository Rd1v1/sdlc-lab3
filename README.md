# LAB 3 — запуск и проверка

Приложение подбирает пароль по локальному учебному хэшу. Поддерживаются MD5, SHA-1, bcrypt и Argon2id. Требуются Windows, PowerShell и Python 3.13+. Для режима `gpu` дополнительно нужна видеокарта с OpenCL-драйвером. Docker не нужен.

## Первый запуск

Откройте PowerShell в корне репозитория `sdlc-lab3`, где находятся `main.py` и `run.ps1`:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/setup.ps1
.venv/Scripts/python.exe main.py
```

Зависимости устанавливаются только в `.venv`; активировать окружение не требуется. Альтернативный запуск с автоматической первоначальной настройкой:

```powershell
powershell -ExecutionPolicy Bypass -File run.ps1
```

Приложение последовательно спрашивает хэш, режим, источник кандидатов, алфавит/длины и число воркеров. Если на всё нажимать Enter, на GPU ищется `123456` среди десяти вариантов `123450`–`123459`. Для полного перебора без известного префикса введите `-` в вопросе о префиксе. Длины относятся к перебираемой части; стандартный предел — 2 млн вариантов.

## Несколько воркеров

| Режим | Что означает `--workers N` |
| --- | --- |
| `threads` | N потоков CPU, диапазон разделён между ними |
| `processes` | N отдельных процессов CPU с собственными диапазонами |
| `gpu` | N параллельных кандидатов в GPU-пакете; номера строк обозначают слоты пакета |

Для CPU по умолчанию используется один воркер, для GPU — 16. GPU-слоты повторно используются в следующих пакетах; это не количество аппаратных ядер видеокарты. Старый параметр `--gpu-batch-size` также поддерживается как синоним числа GPU-воркеров. Потоки и процессы выбираются отдельными режимами.

GPU, четыре воркера; ожидаемый пароль `123456`:

```powershell
.venv/Scripts/python.exe main.py e10adc3949ba59abbe56e057f20f883e --backend gpu --workers 4 --alphabet 0123456789 --prefix 12345 --min-length 1 --max-length 1 --progress
```

Два процесса или два потока CPU; ожидаемый пароль `abc`:

```powershell
.venv/Scripts/python.exe main.py 900150983cd24fb0d6963f7d28e17f72 --backend processes --workers 2 --alphabet abc --min-length 3 --max-length 3 --progress
.venv/Scripts/python.exe main.py 900150983cd24fb0d6963f7d28e17f72 --backend threads --workers 2 --alphabet abc --min-length 3 --max-length 3 --progress
```

Таблица выводится в stderr, итоговый JSON — в stdout:

| Колонка | Содержимое |
| --- | --- |
| `WORKER` | Номер воркера |
| `STATE` | `waiting` — ожидает; `running` — работает; `found` — совпадение; `done` — завершил диапазон/пакет; `stopped` — остановлен после чужой находки; `skipped` — кандидат длиннее GPU-лимита; `error` — ошибка |
| `CHECKED` | Число завершённых проверок этого воркера; на GPU накапливается по пакетам |
| `CANDIDATE (sample)` | Текущий или последний наблюдаемый кандидат |
| `FOUND PASSWORD` | Пароль, для которого именно этот воркер подтвердил совпадение; `-` означает отсутствие находки |

После находки дополнительно выводится полный пароль: `FOUND by worker 3: "123456"`. Остальные воркеры прекращают поиск после текущей проверки/пакета. Для одного целевого хэша обычно результат есть у одного воркера; остальные строки не должны показывать найденный пароль. Повторяющиеся строки словаря могут дать несколько совпадений в одном GPU-пакете.

Фрагмент результата первого примера с четырьмя GPU-воркерами:

```text
WORKER  STATE     CHECKED  CANDIDATE (sample)       FOUND PASSWORD
     1  done            2  "123454"                 -
     2  done            2  "123455"                 -
     3  found           2  "123456"                 "123456"
     4  done            2  "123457"                 -
FOUND by worker 3: "123456"
```

Экран обновляется примерно раз в 0,1 с: быстрые промежуточные кандидаты могут не попасть на экран. Результат совпадения выводится независимо от частоты обновлений. Длинные значения сокращаются в таблице, а найденный пароль сохраняется полностью в отдельной строке и JSON. Ctrl+C останавливает поиск. `--no-progress` отключает таблицу для замеров или обработки JSON.

## Поиск по словарю

Загрузите полный RockYou один раз:

```powershell
.venv/Scripts/python.exe scripts/setup-wordlist.py
.venv/Scripts/python.exe main.py e10adc3949ba59abbe56e057f20f883e --backend gpu --workers 4 --wordlist .tools/wordlists/rockyou.txt --progress
```

Ожидается `123456`, находящийся в первой строке. Файл остаётся в `.tools/wordlists` и не попадает в Git. В интерактивном режиме выберите источник `2`. Префикс к словарю не применяется. CPU-поиск по словарю поддерживает только `--backend threads --workers 1`; выбор нескольких CPU-воркеров предусмотрен для генерации по алфавиту.

## Проверка работы

```powershell
.venv/Scripts/python.exe main.py --help
$env:LAB3_GPU_TESTS = '1'
.venv/Scripts/python.exe scripts/test.py
.venv/Scripts/python.exe -m pip check
```

Проверяются все четыре алгоритма, потоки/процессы, реальные GPU-дайджесты, словарь, распределение кандидатов, счётчики и найденные пароли воркеров, ошибки и отмена. На Windows ожидается один пропуск POSIX-теста сигнала. Для проверки только CPU удалите переменную: `Remove-Item Env:LAB3_GPU_TESTS -ErrorAction SilentlyContinue`; GPU-тесты будут пропущены.

Проверка исчерпания диапазона: здесь ищется `abc`, но в диапазоне только `a` и `b`:

```powershell
.venv/Scripts/python.exe main.py 900150983cd24fb0d6963f7d28e17f72 --backend threads --workers 2 --alphabet ab --min-length 1 --max-length 1 --progress
$LASTEXITCODE
```

Ожидаются `found: false`, `password: null`, две проверки и код `1`. Коды завершения: `0` — найдено, `1` — диапазон исчерпан, `2` — ошибка параметров/устройства/файла, `130` — отмена. При ошибке OpenCL проверьте драйвер или явно выберите CPU-режим: автоматической подмены GPU нет. CPU-воркеров допускается не больше числа логических процессоров (до 64, на Windows до 61 процесса).

GPU: максимум 256 байт на кандидат, bcrypt — 72; Argon2id — 32-байтовый digest и до 32 кандидатов в пакете с дополнительным ограничением по памяти устройства. Для других GPU-хэшей предел пакета — 4096. Криптографические OpenCL-примитивы используются под [MIT](lab3/src/kernels/vendor/LICENSE.txt); генерация кандидатов и управление GPU реализованы в приложении, без запуска hashcat.

## Сравнение с hashcat

Оба приложения выполняют поиск на GPU. Указана медиана трёх запусков: **время поиска в секундах**.

| Алгоритм | Режим | Моё приложение, с | hashcat, с |
| --- | --- | ---: | ---: |
| MD5 | Без словаря | 0.764 | 2.404 |
| MD5 | RockYou | 1.039 | 2.725 |
| SHA-1 | Без словаря | 0.738 | 2.513 |
| SHA-1 | RockYou | 1.046 | 2.953 |
| bcrypt | Без словаря | 1.286 | 8.762 |
| bcrypt | RockYou | 1.655 | 11.357 |
| Argon2id | Без словаря | 0.911 | 5.912 |
| Argon2id | RockYou | 1.237 | 2.866 |

Без словаря: маска `12345?d`, 10 вариантов. RockYou: полный словарь из 14 344 391 строк, пароль `123456` находится в первой строке. Поиск прекращается после находки; время не означает проверку всего словаря.

Измеряется полное время отдельного процесса, включая подготовку GPU. В моём приложении при работе со словарём также учитывается проверка файла. Это время выполнения указанного задания, а не пиковая скорость хэширования.

Подробные условия замеров и отдельный запуск hashcat — в [REPORT.md](REPORT.md). Для анализа длины, алфавита и числа CPU-воркеров:

```powershell
.venv/Scripts/python.exe -m lab3.src.benchmark --repeats 3 --backend processes --workers 1 2 --output artifacts/processes
```
